# Flame 게임 템플릿

새 게임을 시작할 때마다 씬 전환·이벤트 배선·해상도 대응을 다시 만들지 않기 위한 재사용 구조.
[[flame-game]]에서 실제로 돌려보며 다듬은 뒤 `templates/flame-game/`으로 떼어냈습니다.

```bash
scripts/new-flame-game.sh my_game --title "My Game"
```

## 왜 복사가 아니라 스크립트인가

Flutter 프로젝트는 이름이 `pubspec`·iOS/Android 번들 ID·Xcode 프로젝트·`.iml`에 박혀 있어서
`cp -R`은 옛 이름을 곳곳에 남깁니다. 더 중요한 건 **`ios/`·`android/`·`macos/` 폴더가 낡는다**는
것입니다 — 1년 뒤에 복사하면 그 시점 Xcode와 맞지 않는 껍데기를 물려받습니다.

그래서 스크립트는 **`flutter create`로 설치된 툴체인에 맞는 새 플랫폼 껍데기를 만들고 아키텍처만
얹습니다.** 이게 가능한 이유는 템플릿 `lib/`가 **상대 경로 import만** 쓰기 때문입니다 —
패키지 이름을 참조하는 건 테스트 파일 하나뿐이고 스크립트가 치환합니다.

## 구조가 지키는 것

| 규칙 | 이유 |
|---|---|
| 씬끼리 서로 참조하지 않음 (`SceneRequested` 이벤트로만 이동) | 씬을 독립적으로 교체·테스트 가능 |
| 구독 해지를 씬이 관리하지 않음 (`SceneComponent`가 자동 취소) | 스트림 누수는 이 구조의 대표적 실수 — 잊을 수 없게 만듦 |
| 좌표는 항상 디자인 공간(720×1280), 실기기 크기 금지 | 폰·태블릿·데스크톱 창에서 레이아웃이 동일. 카메라가 레터박스 처리 |
| 게임 규칙은 `GameSystem` 구현으로 분리 | 씬이 짧게 유지됨. 시스템 추가 시 다른 코드 불변 |
| 애니메이션은 Flame 이펙트, `update()`의 sin 계산 금지 | 조합 가능·런타임 착탈 가능 |
| 이벤트 버스는 비동기 전달 | 동기 버스는 핸들러가 순회 중 emit해서 재진입 버그를 만듦 |

`core/`는 손대지 않는 것이 기본값입니다. 게임마다 달라지는 건 씬·시스템·아트이지 프레임이 아닙니다.

## 구현 중 테스트가 잡아낸 버그 4개

전부 **플레이어가 먼저 만났을** 종류라 템플릿에 수정된 채로 들어가 있습니다.

1. **`onLoad` 안에서 `await add()`는 끝나지 않는다.** Flame은 `onLoad`가 반환돼야 마운트 큐를
   처리합니다. 첫 씬 전환이 멈추고 이벤트 순서가 뒤집혔습니다.
2. **전환 중 가드가 씬 요청을 조용히 버렸다.** 버튼을 눌렀는데 아무 일도 안 일어나는 버그.
   전환을 원자적으로 만들어 창 자체를 없앴습니다.
3. **로딩 중 교체된 씬이 크래시했다.** 트리에서 분리된 채 `game`에 접근 — 빠른 더블탭이면
   재현됩니다. 마운트 전 의존성 주입(`bindFrame`)으로 차단.
4. **`withFixedResolution`은 뷰파인더가 중앙 앵커다.** 월드 (0,0)이 화면 정중앙에 와서
   좌상단 기준으로 짠 레이아웃이 오른쪽 아래 사분면으로 밀렸습니다. `Anchor.topLeft`로 고정.

## 스캐폴딩 스크립트가 하는 일

`flutter create` → `lib`/`test`/`assets` 이식 → 테스트의 패키지명 치환 → `flame`·`flame_test`
추가 → pubspec 에셋 블록 등록 → 애널라이저 규칙 병합 → 표시 이름 설정 → **`flutter analyze` +
`flutter test`로 검증하고 실패하면 중단**.

> **함정:** `flutter create`가 만드는 `analysis_options.yaml`에는 이미 빈 `rules:` 키가 있어서,
> 새 `rules:`를 추가하면 **중복 매핑 키**로 파일 전체가 파싱 불가가 됩니다. 스크립트는 기존
> `rules:` 아래에 끼워 넣습니다. (실제로 첫 검증에서 이 오류로 실패했습니다.)
