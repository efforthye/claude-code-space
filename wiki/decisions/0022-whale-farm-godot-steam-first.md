# 0022 — WHALE FARM: 웹 설계 리그 + Godot 4 출시 빌드, Steam 선행

> **⚠️ 2026-08-19 완화됨.** "Steam 선행이 전제조건"은 [[0025-whale-farm-korea-first]]로
> 완화되었습니다. 1차 목표 시장이 미국에서 **한국**으로 내려가면서 필요 볼륨이 자릿수
> 낮아졌고, Steam 위시리스트라는 수요 저장 장치가 더 이상 필수가 아닙니다. Steam은 2차
> 채널로 남기고, **웹 무료 데모(Godot HTML5 출력)**가 데모 역할을 대신합니다.
> **엔진 결정(TS 코어 → 웹 리그 → Godot 4 출시 빌드)은 그대로 유효**하며, Godot을 고른
> 이유 중 "단일 소스로 여러 플랫폼 출력"은 웹 데모 경로에서 오히려 더 중요해졌습니다.

## 맥락

두 개의 독립된 질문이 하나로 얽혀 있습니다.

1. **무엇으로 만드나** — 1인 + Claude로 유지 가능하고, iOS에 낼 수 있는 것.
2. **어디에 먼저 내나** — [[paid-appstore-number-one-2026]] §9의 부등식은
   `발매일 미국 iOS 판매량 = 저장된 수요 × 전환율 × 지역·플랫폼 비중 ≥ 5,000`,
   즉 **발매 전 대기 수요 약 10만 명**을 요구합니다. 모바일에는 그 수요를 저장할 그릇이 없습니다.
   위시리스트는 Steam에만 있습니다. 그리고 최근 유료 차트 진입자 전원이 PC/콘솔 후광 보유자였습니다.

## 검토한 안

**엔진**

| 안 | 탈락/채택 이유 |
|---|---|
| Expo / React Native ([[0003-expo-react-native-for-mobile-app]]) | 사내 숙련도가 있고 [[mayo]]에서 검증됨. 그러나 **Steam 출력이 불가** → 수요 저장 전략이 무너짐 → **탈락** |
| Unity | 생태계는 크지만 UI 게임 하나에 과중하고, 런타임 요금 정책 변동 이력이 리스크 |
| **Godot 4 (2D, GDScript)** | iOS·Android·Windows·macOS·HTML5 단일 소스 출력, 무료·로열티 0, UI 중심 2D에 충분, 1인 유지 가능 → **채택** |
| 웹(WebView) 래핑으로 iOS 출시 | 프리미엄 유료 게임을 WebView로 내는 것은 심사 리스크 + 촉감이 나쁨 → 탈락 |

**출시 순서**

| 안 | 결과 |
|---|---|
| 모바일 단독 출시 | 수요 저장 장치가 없어 1위 확률이 사실상 0. 선례도 없음 |
| **Steam 데모 선행 → PC 정식 + iOS 동시 발매** | 위시리스트로 수요를 저장하고, 데모가 **유료앱이 제공할 수 없는 체험판**을 대행([[0021-whale-farm-premium-no-iap]]) → **채택** |

## 결정

**3층 구조로 갑니다.**

1. **경제 코어는 플랫폼 중립 TypeScript** (`apps/whale-farm/sim/`).
   의존성 0, Node 24 네이티브 실행. 밸런스의 유일한 원본.
2. **웹은 설계 리그(design rig)** — 플레이어블 프로토타입 + 몬테카를로 밸런싱을 같은 코드로 돌립니다.
   재미와 밸런스를 여기서 확정합니다. 출시 채널이 아닙니다.
3. **출시 빌드는 Godot 4** — 확정된 경제 규칙을 GDScript로 이식하고, iOS와 Steam에 같은 소스로 냅니다.

**출시 순서:** Steam 페이지 + 무료 데모 선행(수 개월) → 위시리스트 축적 → PC 정식 + iOS **동시 발매일 스파이크**.

**게이트:** 발매 1주 전 위시리스트 10만 미달이면 미국 종합 1위 시도를 접고
카테고리 1위 / 한국 1위로 목표를 하향합니다([[whale-farm]] §7.4).

## 결과

- **얻는 것:** 밸런스 사본이 하나뿐입니다. `node sim/montecarlo.ts`가 밸런스의 심판이고,
  같은 코드가 프로토타입을 돌리므로 "문서와 게임이 다르다"가 구조적으로 불가능합니다.
- **얻는 것:** 웹 리그는 지금 당장 폰에서 플레이 가능합니다 — 재미 검증에 빌드 파이프라인이 필요 없습니다.
- **비용:** 경제 규칙을 TS → GDScript로 **한 번 이식**해야 합니다. 규칙이 순수 함수 + 상수 테이블이라
  이식 비용은 낮지만 0은 아닙니다. 이식 후에는 몬테카를로 하네스를 GDScript 쪽에도 두어
  두 구현이 같은 시드에서 같은 결과를 내는지 대조합니다(회귀 테스트).
- **비용:** Godot이 아직 이 개발 머신에 설치되어 있지 않습니다. M5(iOS 이식) 진입 시 설치합니다.
- 리스크: Steam 선행은 몇 달의 리드타임을 요구합니다. "만들고 나서 홍보"가 아니라
  **"데모부터 내고 만들면서 모은다"**가 일정의 형태여야 합니다.
